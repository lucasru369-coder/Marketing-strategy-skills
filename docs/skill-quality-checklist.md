# Skill Quality Checklist

Use this checklist when creating or revising a skill in this repository.

## 1. Scope and discoverability

- [ ] The skill has a clear, unique name.
- [ ] The description explains what the skill does and when to use it.
- [ ] The skill has a defined role and outcome.
- [ ] The scope does not duplicate another skill without explaining the relationship.
- [ ] The skill can be used independently where appropriate.

## 2. Workflow quality

- [ ] The workflow has a logical sequence.
- [ ] Inputs and missing-information handling are explicit.
- [ ] Facts, assumptions, estimates, and recommendations are distinguished.
- [ ] The guidance supports decisions rather than merely listing concepts.
- [ ] The level of detail is appropriate to the task.

## 3. Output quality

- [ ] Expected output formats are described.
- [ ] Templates are practical and reusable.
- [ ] Tables have clear fields and definitions.
- [ ] Examples are labeled as fictional when data is invented.
- [ ] Recommendations include rationale and next steps.

## 4. Reliability and safety

- [ ] No personal or confidential information is included.
- [ ] No unsupported statistics or fabricated sources are presented as facts.
- [ ] Uncertainty and limitations are visible.
- [ ] Legal, privacy, cultural, and accessibility considerations are addressed where relevant.
- [ ] The skill does not claim capabilities or approvals it cannot guarantee.

## 5. Repository consistency

- [ ] The file uses the repository's naming convention.
- [ ] Markdown headings are hierarchical and readable.
- [ ] Relative links resolve to existing files.
- [ ] The README index is updated when a skill is added.
- [ ] Related skills and templates are cross-referenced.
- [ ] Commit messages describe the actual change.

## 6. Maintenance

- [ ] Dated facts and fast-changing references are not hardcoded unnecessarily.
- [ ] Templates can be adapted without rewriting the skill.
- [ ] Duplicate guidance is minimized.
- [ ] The change has been checked against adjacent skills.
- [ ] Future maintenance requirements are clear.
